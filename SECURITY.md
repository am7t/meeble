# Security notes

The current release is a local-only Django app with email/password registration, sign-in, sign-out, SQLite, Django session/CSRF middleware, and relational profile/post/comment/reaction/follow tables. The profile editor requires authentication and always loads the current user's profile; its form does not accept an owner ID. Public profile pages and the people directory expose display names, handles, bio, customization, and aggregate counts, never email addresses or credentials. Profile and feed post queries enforce public/follower/private visibility on the server. Feed APIs bind new records to the session user and enforce post edit/delete ownership. Follow mutations require a session and exclude the current user as a target. The sample feed and its browser-storage interactions remain fictional showcase data, not trusted or private storage. Upload validation/private media, login throttling, and payment processing are not implemented yet.

User-entered post and comment text is rendered as escaped text. Do not add arbitrary HTML, CSS, or JavaScript input. The local development configuration uses a development-only key and `DEBUG=True`; bind only to loopback and never expose this configuration to other machines. Before exposing the app on a network, configure a private key and production settings, complete object-level authorization checks for each feature, and add private media delivery and abuse controls. A localhost app is not a public service, and local database content is visible to the device owner.
