# Security notes

The current release is a local-only Django app with email/password registration, sign-in, sign-out, SQLite, Django session/CSRF middleware, and relational profile/post/comment/reaction/follow tables. No profile or feed endpoints currently expose those records; object-level authorization policies must be implemented before feature workflows serve or change them. Upload validation/private media, login throttling, and payment processing are also not implemented yet. Browser storage is editable by the device owner and must not be treated as trusted or private storage.

User-entered post and comment text is rendered as escaped text. Do not add arbitrary HTML, CSS, or JavaScript input. The local development configuration uses a development-only key and `DEBUG=True`; bind only to loopback and never expose this configuration to other machines. Before treating the app as multi-user or reachable from other machines, configure a private key and production settings and implement server-side authentication, authorization, validation, private media delivery, abuse controls, and security tests. A localhost app is not a public service, and local database content is visible to the device owner.
