# Security notes

The current release is a local-only Django app with email/password registration, sign-in, sign-out, SQLite, Django session/CSRF middleware, and relational profile/post/comment/reaction/follow/story tables. The profile editor requires authentication and always loads the current user's profile; its form does not accept an owner ID. Public profile pages and the people directory expose display names, handles, bio, customization, and aggregate counts, never email addresses or credentials. Profile, feed post, and story queries enforce public/follower/private visibility on the server. Feed and story APIs bind new records to the session user and enforce owner-only mutations. Follow mutations require a session and exclude the current user as a target. Story uploads are size/type/pixel limited, decoded and re-encoded as JPEG with metadata removed, stored outside static assets, and streamed only through an authenticated visibility-checked view. Expiration is enforced on list and image reads; run `python manage.py purge_expired_stories` periodically to delete expired rows and files. The sample feed and its browser-storage interactions remain fictional showcase data, not trusted or private storage. General post-image upload, login throttling, and payment processing are not implemented yet.

User-entered post, comment, and story text is rendered as escaped text. Do not add arbitrary HTML, CSS, or JavaScript input. The local development configuration uses a development-only key and `DEBUG=True`; bind only to loopback and never expose this configuration to other machines. Before exposing the app on a network, configure a private key and production settings, review object-level authorization for every feature, and add abuse controls. A localhost app is not a public service, and local database content is visible to the device owner.
